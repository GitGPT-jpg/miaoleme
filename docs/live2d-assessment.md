# Live2D 接入评估（喵了么）

日期：2026-10-21　版本：v0.5.5　结论：**暂不直接接 Live2D；先做自研 2D 网格/物理层，保留后续切换路径**

---

## 1. 当前问题（为什么帧“怪”）

| 现象 | 根因 | 影响 |
|---|---|---|
| 动作帧忽大忽小、位置跳动 | AI 逐帧生成，画布尺寸/角色占比/脚底基线不一致 | 序列播放时像“换了一只猫” |
| 转身/姿态之间不连续 | 每帧独立生成，没有共享骨骼与姿势约束 | 动作像幻灯片而非运动 |
| 眨眼/压耳切换有细微跳变 | 闭眼/压耳头与主头尺寸、角度不完全一致 | 瞬态违和 |
| 缺“活着”的微动 | 静态帧 + 整体变换，缺少眼神、呼吸、重心变化 | 像贴纸而非生物 |

## 2. 三条可走路线

### A. 官方 Live2D Cubism（真骨骼 + 网格蒙皮）
- 运行时：Cubism SDK for Web（PixiJS/自研渲染均可）
- 模型：`.model3.json` + 分层纹理 + 参数/物理/表情，必须用 **Cubism Editor** 绑定
- 授权：Cubism Core 为 Live2D 专有；SDK 有营收门槛的免费额度，超限需付费；模型需自有版权或商用授权
- 工作量：每只猫需要美术拆分 → 网格绑定 → 参数/物理 → 表情/动作（数小时~1 天/只，且需要 Editor）
- 结论：**效果上限最高**，但“用户上传照片自动生成”无法端到端自动化（AI 无法产出可用的网格绑定），且授权需法务确认

### B. 自研 2D 网格伪 Live2D（推荐现在做）
- 用 WebGL/Canvas 对现有部件做：**网格变形（warp）+ 弹簧物理 + 视线追踪 + 眨眼/呼吸**
- 无需 Live2D 授权，完全可控；部件已由生成流程产出（身/头/尾/闭眼/压耳）
- 可以达到“80% 的活物感”，失败可回退现有序列帧
- 工作量：中等（渲染层 1–2 天，可增量落地）

### C. Spine / 其他商业 2D 骨骼
- 编辑器付费、导出格式私有；同样需要人工绑定；生态不如 Live2D
- 结论：不优先

## 3. 推荐路线（分阶段）

**阶段 1（本轮已开始）— 让现有骨骼“活”起来**
1. 光标注视：头部跟随鼠标（带弹簧阻尼），身体轻微倾靠
2. 呼吸/心跳：胸腔缩放 + 微上下浮动（已有，改为不规则周期避免机械感）
3. 尾巴物理：弹簧跟随身体运动，停止时缓慢摆动
4. 眨眼/耳朵：随机间隔（已有），加“连续两次眨眼”等自然变化
5. 动作帧归一化：按 alpha 包围盒统一高度与脚底基线，消除忽大忽小

**阶段 2（v0.6.0 已完成核心项）— 伪 Live2D 网格层**
- ✅ 头部分带 warp（3 带竖向渐变；2×2 网格为完整版，当前用分带近似，接缝已消除）
- 身体纵向网格，呼吸与重心变化更自然
- ✅ 瞳孔 saccade（上两带叠加随机微跳，1.6–4.4s 一次）
- ✅ 尾巴临界阻尼弹簧（真实惯性）
- 保留序列帧作为“大动作”，网格层负责“待机生命感”

**阶段 3（可选，需资源）— 真 Live2D**
- 采购/自制 1–3 个**明确商用授权**的 Cubism 模型作为“官方形象”
- 用户上传照片继续走阶段 2 的伪骨骼（自动生成）
- 需要：Cubism Editor 授权、绑定人力、法务确认 SDK 条款

## 4. 风险与边界
- AI 生成帧无法保证跨帧一致性，归一化只能缓解尺寸/基线，不能修复姿态漂移
- 用户照片的毛发/遮挡会限制部件拆分质量，极端姿态仍可能出现接缝
- Live2D 真骨骼需要人工绑定，无法与“上传即生成”完全自动化兼容
- 授权：Cubism SDK/Core 商用条款需按公司营收确认；示例模型不可直接商用

## 5. 验收指标（“像活的”）
- 空闲 30 秒内至少出现：呼吸、眨眼 ≥2 次、尾巴摆动、1 次耳朵动作、头部随光标微动
- 动作切换无明显尺寸跳变（归一化后高度差 < 2%）
- 连续 10 分钟 CPU 增幅 < 3%（30fps 限流 + 轻量网格）
