## 1. 产品概述

**一句话定位**：一只住在桌面上的 3D 猫咪——把喝水、久坐、会议、DDL 这些冷冰冰的提醒变成"养猫"式互动；上传自家猫的照片，还能生成专属桌宠。

**要解决的问题**
- 办公族久坐、忘喝水，系统弹窗提醒容易被随手关掉，逐渐失效
- 会议、DDL 散落各处，临近才想起
- 午饭"吃什么"选择困难，工作间隙缺少轻量放松

**解法**：用陪伴感替代命令式提醒。猫咪到点"讨水""讨饭"，用户喂它的同时完成了自己的打卡；番茄钟、复盘、小游戏把效率工具和情绪价值放在同一个入口。

**产品原则**
1. 陪伴不打扰：桌面空白处点击穿透，不挡工作；支持免打扰时段与稍后提醒
2. 提醒即互动：完成提醒 = 喂猫，即时正向反馈（动画 + 亲密度）
3. 诚实反馈：非饭点不"假装喂成功"、重启不虚增番茄数、生成失败如实展示并可重试
4. 本地优先：数据存本机；未配置生成服务时不发起任何网络请求

## 2. 目标用户与场景

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 久坐的知识工作者（研发/设计/运营） | 每天 8h+ 面对电脑，会议多 | 被"温柔地"提醒喝水、起身、开会、赶 DDL |
| 猫奴 / 桌宠爱好者 | 重视情感陪伴 | 把自家猫"搬"到桌面上 |
| 学生 / 自律人群 | 需要专注与复盘习惯 | 番茄钟 + 每日复盘 + 连续打卡 |

**典型场景**
- 10:30 猫咪在屏幕角落撒娇"我口渴了…主人也喝点水吧" → 点喂水 → 猫低头喝水，亲密度 +1，用户顺手喝水
- 会前 5 分钟弹出系统通知，点击直接打开控制台
- 11:50 不知道吃什么 → 吃饭转盘转一下，顺便看看这口"赚了还是亏了"
- 下班前写每日复盘（完成/收获/卡点/明日计划），连续打卡天数 +1

## 4. 功能详述

### 4.1 桌宠本体
- **形态**：内置喵喵 / 小铁 / 咕叽三种，外加用户上传生成的自定义形象；托盘可随时切换
- **待机"生命感"（2D 骨骼）**：头/身体/尾巴拆分部件；不规则呼吸、头部分带 warp（抬头/歪头不再整体旋转）、瞳孔随机微动、眨眼（3–6s）、压耳（8–15s）、尾巴临界阻尼弹簧、视线跟随光标；渲染 30fps 限流
- **大动作（序列帧）**：走路×4 / 打滚×5 / 舔毛×4 / 干饭×4 / 喝水×4 / 伸懒腰×3 关键帧；播放动作时骨骼暂停、结束自动恢复；帧按 alpha 包围盒归一化，避免忽大忽小
- **交互**：拖动摆放并记忆位置；多显示器变更后自动回到可见区域；空白处点击穿透；悬停呼出底部快捷菜单；会自己在桌面游走
- **单实例**：重复启动自动退出，避免双开

### 4.2 照片生成专属桌宠（核心差异化）

流程：控制台 → 桌宠 → 上传我的图片（可多选）→ 后台生成、进度可见 → 素材齐全后热刷新上桌。

| 规则 | 说明 |
|---|---|
| 输入 | 单次最多 6 张，取最多 4 张作参考图（多图提升"同一只猫"的一致性）；逐张校验体积与文件类型（魔数嗅探） |
| 产出 | 6 个姿势帧（站立/行走/打滚/舔毛/吃饭/睡觉，透明底手办风）+ 5 个骨骼部件（身体/头/尾巴/闭眼/压耳），共 11 个素材 |
| 调度 | 站立帧优先，其余并发 2；429/5xx/超时最多额外重试 2 次，认证/请求错误不重试；单帧 5 分钟、整任务 10 分钟截止 |
| 隔离 | 每次上传独立输入快照与任务 ID，旧任务迟到结果不覆盖新形象；换图后骨骼部件做来源校验，不混用 |
| 质量闸门 | 丢弃空/过小/碎裂/与站立帧比例失衡的帧（计为失败、可重试）；提示词约束"四条腿、一条尾巴、自然体态" |
| 状态 | 全部成功 / 部分成功（可重试失败项）/ 失败 / 已取消 / 未配置；关闭面板再打开可继续看真实进度 |
| 降级 | 未配置服务时不发请求、只展示原图（写实模式：圆角 + 呼吸微动）；部件缺失回退序列帧；自定义形象缺喝水/伸懒腰帧时只换文案不换图，不跨猫错配 |

**服务配置**：设置 → 图像生成服务，选择服务商（Comate / 千帆）、填写接口地址与身份信息 → 保存 → 测试连接。配置写入用户目录（权限 600），不进安装包、不写日志。千帆图生图协议尚未联调。

### 4.3 喂养玩法（提醒的游戏化）
- **喂水**：到点猫咪讨水 → 用户喂水 → 播放喝水动画，亲密度 +1；只有回应讨水请求才加分，喝水打卡 5 分钟节流防刷
- **喂饭**：午/晚饭点讨猫粮，未喂隔几分钟再催；喂粮后播放吃饭动画；非饭点喂饭不记账、不假装成功；只标记当前餐次，跨天清理
- **撸猫**：增加成长值，限频 + 每日上限
- **入口**：悬停菜单、控制台、托盘均可喂；待喂时底部图标显示小红点

### 4.4 提醒系统

| 提醒 | 规则 |
|---|---|
| 喝水 | 间隔可调，以猫咪讨水形式出现 |
| 久坐 | 按间隔提醒起身活动 |
| 会议 | 提前 5 分钟 + 到点 |
| DDL | 提前 1 天 / 1 小时 / 到点 |
| 免打扰 | 自定义时段，支持跨午夜 |
| 稍后提醒 | 贪睡 10 / 20 / 30 分钟，只作用于当前这条提醒 |

系统通知点击可唤起控制台。

### 4.5 专注：番茄钟
- 专注/休息自动循环，完成数计入成就
- 重启恢复：未到期的番茄继续计时；已到期的只提示、不虚增完成数

### 4.6 吃饭
- **吃饭转盘**：午餐/晚餐独立菜单，可自定义并持久化；转盘动画，指针落点与结果一致并高亮
- **食物寿命实验室**：18 种常见食物的营养拆解 + "这口 ±几分钟"趣味估算与年度外推；记住上次选择；界面标注"趣味估算，非医疗建议"

### 4.7 每日复盘
- 字段：完成 / 收获 / 卡点 / 明日计划 + 能量星级 + 心情
- 连续打卡天数、历史记录、JSON 导入导出
- 当天首次复盘给桌宠加亲密度

### 4.8 小游戏
石头剪刀布（战绩持久化）、猜数字、记忆翻牌、反应力测试。

### 4.9 养成与个性化
- 亲密度 / 喝水 / 番茄成就 + 等级进度条
- 暗色模式、开机自启、全局快捷键、菜单栏小猫头托盘图标（含 2x 高清）

### 4.10 一键演示（路演模式）
托盘或设置页启动，约 30 秒自动串场：打招呼 → 伸懒腰 → 打滚 → 吃饭转盘 → 喂水/喂粮 → 番茄钟 → 游戏。配套 `tools/demo-seed.js` 写入演示数据，`--restore` 恢复个人数据。

## 5. 关键用户流程

**首次上手**
1. 安装并打开 → 桌宠出现在屏幕角落，控制台同时打开
2. （可选）设置 → 图像生成服务 → 保存并测试连接
3. 桌宠页上传 1–6 张照片 → 查看进度（实测 11 个素材约 7 分钟）→ 专属形象上桌
4. 关闭控制台不退出，程序常驻菜单栏托盘

**日常循环**：讨水/讨饭 → 喂养（动画 + 亲密度）→ 番茄专注 → 饭点转盘 → 下班复盘 → 等级成长

## 6. 非功能需求与现状

| 维度 | 要求 / 现状 |
|---|---|
| 性能 | 空闲 CPU ≈ 0%；游走峰值约 2.7%（位置 IPC 限流 ~30Hz）；主进程 RSS 约 60–150MB |
| 稳定性 | 单实例锁；30 分钟观察 CPU 峰值 0.7%、内存无持续增长（未做 12 小时长稳） |
| 数据可靠 | 本地 JSON 原子写入；损坏自动备份为 `*.corrupt-<时间戳>` 后重建；旧版"零度突破"数据目录自动迁移 |
| 安全 | contextIsolation + sandbox + CSP；IPC 只信任本应用窗口并校验输入；上传体积/魔数校验；生成接口强制 HTTPS、响应 20MB 上限、错误不回显上游响应体 |
| 隐私 | 数据只存本机；照片仅在用户主动生成时发送到其配置的服务；凭据文件权限 600，不进安装包与日志 |
| 质量 | 100 项单元测试全部通过（node:test，2026-10-21 实测） |

数据位置：macOS `~/Library/Application Support/miaoleme/zerobreak-store.json`；Windows `%APPDATA%/miaoleme/zerobreak-store.json`。

## 7. 平台、技术与分发

| 平台 | 运行时 | 产物 | 状态 |
|---|---|---|---|
| macOS（Apple Silicon） | Electron 45 | `.dmg` / `.zip` | 主平台，可日常使用；未签名/公证 |
| Windows x64 | Electron 33（受下载页 100MB 上限） | 免安装 zip / tar.xz | 内测；未经 Windows 真机验证；NSIS 安装包需 CI 构建 |
| Linux | — | AppImage | 已配置打包目标，未构建验证 |

**技术方案**：Electron + 原生 JS/CSS（无前端框架）。主进程 `main.js` 负责窗口、托盘、调度、通知、喂养与生成编排；`preload.js` 提供受限 IPC 桥；`renderer/` 为桌宠窗口与控制台；`lib/` 为可单测的纯函数模块（调度、喂养、番茄、转盘、生成任务、帧质量、骨骼/warp/视线、存储等）。

**分发渠道**：popo 落地页（全公司可见）、临时下载页（附 SHA-256）、GitHub 私有仓库 `GitGPT-jpg/miaoleme`。

## 8. 已知限制与风险

1. 原生 UI 交互（点击穿透、拖拽、托盘、通知点击）未做自动化验证，需人工逐项验收
2. Windows 未经真机验证；内测包仍为 Electron 33（已 EOL），正式分发前需升级并冒烟
3. 安装包未签名/公证，首次打开需右键 → 打开
4. 自定义形象暂无喝水/伸懒腰动作帧（只换文案、不换图）
5. AI 生成帧无法保证跨帧完全一致，质量闸门只能拦截明显的坏帧
6. 千帆图生图协议未联调，不宣称兼容
7. 商用授权：内置 3D 帧由图像生成模型制作，商用分发前需确认模型输出与素材的授权条款
8. 无使用数据埋点（纯本地），产品指标暂无法客观度量

## 10. 成功指标（建议）

| 类型 | 指标 |
|---|---|
| 生命感 | 空闲 30 秒内出现呼吸、≥2 次眨眼、尾巴摆动、1 次耳朵动作、头部随光标微动；动作切换高度差 < 2%；连续 10 分钟 CPU 增幅 < 3% |
| 生成 | 11 素材全部成功的占比、平均生成耗时、重试后补齐率 |
| 习惯 | 日均喂水次数、番茄完成数、复盘连续天数、7 日留存 |

生成与习惯类指标依赖埋点或用户自愿导出的数据，当前版本尚不具备。
